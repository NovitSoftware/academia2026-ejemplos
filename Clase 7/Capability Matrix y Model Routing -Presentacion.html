2.2 · Capability matrix

La ficha dice, la evaluación decide

Ficha del modelo

  • Soporta tool calling
  • Contexto de 128.000 tokens
  • Acepta imágenes

Nuestra evaluación

  • Acierta la tool en 17 de 20 casos de reservas
  • Después de 40.000 tokens olvida instrucciones
  • Lee facturas impresas; falla con remitos a mano

→ La documentación dice si una capacidad existe; solo la evaluación dice si alcanza.

La matriz tiene fecha: se revisa con cada modelo nuevo o cambio de precio.

2.4 · Model routing

Cinco estrategias de routing

Reglas
Condiciones fijas en código.
"Si trae imagen, visión"
+ Predecible y gratis
− No ve la dificultad
Clasificación
Un modelo chico etiqueta el pedido.
"simple" o "complejo"
+ Se adapta al contenido
− Suma una llamada
Costo
Empieza barato y escala si no valida.
Cascada
+ Baja el promedio
− Lo difícil paga dos veces
Latencia
El que responde más rápido ahora.
Proveedor A o B
+ Cuida la experiencia
− Hay que medir en vivo
Capacidad
Filtra con la matriz.
"Contexto largo, ventana grande"
+ Evita modelos incapaces
− Matriz al día

Se combinan: capacidad filtra, reglas o clasificación eligen, cascada corrige.

Cascada: probar primero con el modelo barato y pasar al caro solo si hace falta.
2.4 · Model routing

Reglas primero, clasificación cuando no alcanzan

Por reglas
def elegir_modelo(pedido):
    if pedido.imagenes:
        return "generalista"
    if pedido.tokens > 100_000:
        return "contexto-largo"
    if pedido.tarea in ("clasificar", "extraer"):
        return "economico"
    return "generalista"
Por clasificación
etiqueta = llm("economico").clasificar(
    mensaje, opciones=["simple", "complejo"])
modelo = {"simple": "economico",
          "complejo": "razonamiento"}[etiqueta]
simple"¿Hasta qué hora abren el domingo?"
complejo"Somos 40, dos celíacos, presupuesto $500.000"
Clasificador: modelo que asigna una etiqueta de una lista cerrada.
