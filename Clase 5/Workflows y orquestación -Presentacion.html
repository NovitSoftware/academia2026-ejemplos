1.1 · Workflow vs agente

¿Quién decide el camino?

Workflow determinístico

El código define los pasos y su orden. El LLM trabaja dentro de pasos concretos. Mismo input, mismo recorrido.

intencion = llm.clasificar(mensaje)
if intencion == "reserva":
    datos = llm.extraer_datos(mensaje)
    r = api.crear_reserva(datos)
    return llm.redactar(r)

Agente autónomo

El LLM recibe un objetivo y tools, y en un loop decide qué hacer, mira el resultado y sigue.

while not terminado:
    accion = llm.decidir(objetivo,
                 historial, tools)
    resultado = ejecutar(accion)
    historial.append(resultado)
Tool: función que el modelo puede pedir que se ejecute (consultar, crear, enviar). Loop: ciclo decidir → ejecutar → observar.
1.1 · Workflow vs agente

Por dentro, un agente es un loop

Objetivo"Averiguá por qué no cierra la caja de Pocitos"
Decidir¿qué tool uso ahora?
Ejecutarver_ventas("Pocitos")
Observarfaltan 2 tickets de tarjeta
¿Terminé?no: vuelve a decidir · sí: responde
IngredientesObjetivoToolsHistorialCondición de fin

Ningún paso está escrito de antemano: el camino aparece mientras el agente trabaja.

Historial: lo que el agente hizo y vio hasta ahora; entra en cada decisión. Condición de fin: lo que indica que la tarea terminó.

Los cinco primeros son workflows: el código sigue mandando. Cada escalón suma flexibilidad… y costo.

Patrón: forma probada de organizar las llamadas al modelo. Autonomía: cuánto decide el modelo por su cuenta.
1.3 · Patrones · Prompt chaining

Pasos fijos, uno detrás de otro

La salida de un paso es la entrada del siguiente. Entre pasos, un gate en código corta si algo salió mal.

Mensaje"Quiero reservar el sábado a las 21"
1 · Extraerfecha, hora, personas
Gate¿Están los 3 datos?
2 · Consultardisponibilidad
3 · Redactarla respuesta

El gate falla: falta "personas"

No se sigue. Se repregunta: "¿Para cuántas personas es la reserva?"

Gate: chequeo en código (no en el LLM) entre dos pasos. Encadenar: usar la salida de una llamada como entrada de la siguiente.

1.3 · Patrones · Parallelization

Varias llamadas al mismo tiempo

Sectioning · partes distintas

Cada llamada hace una parte de la tarea, en paralelo.

AResponde la consulta del cliente
BRevisa si pide datos de gerencia

→ se combinan: si B detecta algo, la respuesta de A no sale.

Voting · la misma tarea varias veces

"¿Es un reclamo grave?"

LLM 1grave
LLM 2grave
LLM 3leve

→ 2 de 3 dicen grave: se escala.

Paralelo: las llamadas corren al mismo tiempo, no una después de otra. Escalar: derivar a una persona.
1.3 · Patrones · Orchestrator-workers

Las subtareas se deciden en el momento

Orquestador"Armame el informe mensual de las 3 sucursales"
WorkerCentro
WorkerPocitos
WorkerCarrasco
WorkerComparar con el mes anterior
Orquestadorjunta los resultados y redacta el informe

Diferencia con parallelization: acá nadie fijó las subtareas de antemano; las decide el orquestador según el pedido.

Orquestador: LLM que planifica y reparte el trabajo. Worker: LLM que resuelve una subtarea puntual.
1.3 · Patrones · Evaluator-optimizer

Generar, evaluar, corregir

Generadorredacta la respuesta a un reclamo
Evaluadoraprueba o devuelve feedback
Vuelta 1✗ Cita la política v1 (vieja)
Vuelta 2✗ Promete un reembolso fuera de política
Vuelta 3✓ Aprobada: se envía
Criterios claros del evaluador
Tono empático
Cita la política vigente (v3)
No promete reembolsos fuera de política
Corte: máximo 3 vueltas
Feedback: qué falla y cómo corregirlo, en palabras. Máximo de vueltas: si no aprueba, se escala en lugar de seguir.

1.4 · Costos de agregar autonomía

La autonomía se paga

Tokens10 a 30 llamadas donde un workflow hace 2
Latenciacada vuelta del loop suma segundos
Previsibilidadmismo pedido, caminos distintos
Errores compuestoslos errores de cada paso se multiplican
Riesgomás tools, más cosas que pueden salir mal
Si cada paso acierta el 95%…
95%con 1 paso
60%con 10 pasos
0,95 × 0,95 × … (10 veces) ≈ 0,60

Se agrega autonomía cuando mejora el resultado de forma medible, no porque "suena más potente".

Token: unidad de texto que procesa (y cobra) el modelo. Error compuesto: la chance de que toda la cadena salga bien baja con cada paso.
