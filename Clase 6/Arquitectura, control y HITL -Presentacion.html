Cuatro formas de armar el sistema

Agente únicoUn agente, un prompt, todas las tools.Ventaja+ Simple de construirRiesgo− Se confunde con muchas toolsEjemploBot de preguntas frecuentes
Router + especialistasUn router deriva a agentes chicos.Ventaja+ Prompts cortos, permisos por rolRiesgo− Punto único de fallaEjemploClientes / personal / gerencia

4.3 · Control de ejecución

Todo loop necesita un freno

Iteracionesmáximo 15 llamadas a tools
Costomáximo USD 0,50 por pedido
Timeout2 minutos por conversación
Señal de fintool finalizar() o end_turn
Objetivo verificablela reserva existe y está "confirmada"
for paso in range(MAX_PASOS):
    if costo > MAX_COSTO or vencio():
        return escalar("límite", estado)
    accion = llm.decidir(estado)
    if accion.tipo == "finalizar":
        return accion.respuesta
    if es_repetida(accion, historial):
        return escalar("loop", estado)
    estado = ejecutar(accion, estado)
return escalar("máximo de pasos", estado)
Stopping condition: regla que termina el loop. end_turn: el modelo indica que terminó y no pide más tools.

5.2 · Lectura vs escritura

Lectura: consultar sin cambiar nada. Escritura: crear, modificar, borrar o enviar algo.
5.3 · Human-in-the-loop

¿Quién dice que sí?

Confirmación · el mismo usuario

"Voy a cancelar tu reserva R-1043 del sábado a las 21. ¿Confirmás?"

Aprobación · otra persona

Un reembolso de más de $10.000 queda pendiente hasta que lo aprueba el encargado.

def reembolsar(reserva_id, monto, aprobacion_id=None):
    if monto > LIMITE_SIN_APROBACION \
       and not aprobacion_valida(aprobacion_id):
        return {"estado": "pendiente_aprobacion"}
    return pagos.reembolsar(reserva_id, monto)

La regla vive en el código, no en el prompt: el modelo no puede saltear la aprobación aunque se lo pidan.

Human-in-the-loop: una persona aprueba, corrige o decide en puntos definidos. Acción crítica: la que se define de antemano como de alto riesgo.
